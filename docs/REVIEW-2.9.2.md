# 2.9.2 代码审查与验证记录

审查日期：2026-11-09。基线：2.9.1，提交 `ae89e87`。

## 已修复的问题

| 区域 | 原来的问题 | 现在的处理 |
| --- | --- | --- |
| 自动同步 | 主线程执行最长 5 秒的联网探测 | 后台线程完成，主线程继续处理窗口事件 |
| 退出 | 阻塞等待并在 20 秒后强制终止同步，可能中断写入；超时分支还会引用未赋值的局部 QApplication | 请求安全停止，用定时器等线程结束，再释放资源退出 |
| 网络 | urllib 默认重定向可能把 Authorization 转发到其它来源 | 带 Token 的请求只允许同来源 HTTPS 重定向 |
| 自动登录 | Python 仅判断 endswith("tsinghua.edu.cn")，相似域名也可能收到含密码脚本 | 在发送脚本前验证完整域名边界、HTTPS 与 443 端口 |
| 模型请求 | 拒绝的 Token 仍先下载前端包；每个包都获得完整超时 | 先验证 Token；页面与多个包共享请求预算；回退结果缓存 5 分钟 |
| 备份清理 | `[-0:]` 等价于整个列表；保留份数为 1 时无法清理 | 显式保留最近 keep 份普通备份，原始备份另外保护 |
| 分组快照 | 删除过期条目所在目录时，会删掉同目录仍被保留的其它文件 | 只删除没有任何保留条目的快照目录 |
| 索引自愈 | 同一快照的 source.txt 被最后一个源文件覆盖 | sources.json 保存每个备份文件的来源；旧索引有效时补齐 |
| 旧快照 | 丢失索引的旧多文件快照无法确定对应来源 | 跳过并记录原因，保留文件；不猜测还原位置 |
| 整文件还原 | 不验证 SHA256，损坏密文可能被当作旧明文重新加密 | 校验与解密失败时保留当前文件，阻止错误迁移 |
| SQLite | 临时明文落盘；备份失败会复制缺少 WAL 的主文件 | 一致性备份到内存，直接加密落盘；失败阻止后续写入 |
| 备份读取 | 新建管理器后重新读取每份密文，索引自愈也读取完整文件 | 已标记密文不重读正文，自愈只读 64 字节头部 |
| 异常配置 | JSON 类型不对、Infinity/NaN 可能引发崩溃或缓存长期有效 | 恢复字段默认类型，处理数值溢出，拒绝非有限缓存时间 |
| 失败反馈 | 勾选同步后最小化时，失败也会隐藏主窗口 | 仅成功后最小化 |

## 验证方法

- 全量测试：`.venv\Scripts\python.exe -m unittest discover -s tests -t .`，228 项通过。
- 新增 `tests/test_review_regressions.py`，27 项测试，包含真实 HTTP 重定向、本地 SQLite WAL、
  DPAPI、真实 Qt 后台线程和 GUI 事件循环；其它既有测试同步适配新后台入口与文档规定的保留份数。
- 慢网络与安全退出测试均要求入口在 0.5 秒内返回；后台阻塞期间 Qt 定时事件仍被处理，写入完成后才退出。
- 失败模型请求在 5 分钟内重复调用时只抓取一次前端列表，到期后重新尝试。
- 用 Path.read_bytes 拦截器确认已加密备份不会在每次读取索引时重读正文。
- 执行 `compileall`、`pip check`、`git diff --check`；打包后分别运行两种发行形态的 `--selftest`，同时验证 SQLite WAL 一致性备份、DPAPI、TLS 和浏览器取假 Token。
  自检默认使用临时目录，不读取真实 private 指针。
- 多文件 ZIP 继续作为主下载，单文件 EXE 作为兼容备用。Windows EXE 文件属性与 APP_VERSION 一并更新。

## Python 依赖漏洞检查

使用独立工具环境运行 pip-audit，检查 `.venv/Lib/site-packages` 中全部安装包（包含运行依赖、
传递依赖与构建工具）。初次检查发现 pip 25.0.1 和 setuptools 84.0.0 的已知漏洞条目。
已升级到 pip 26.3、setuptools 84.2.1，并在 requirements.txt 固定 setuptools 版本。
复扫 16 个安装包，未发现已知 Python 包漏洞，结果留档为
[dependency-audit-2.9.2.json](dependency-audit-2.9.2.json)。相关通告：[pip](https://github.com/advisories/GHSA-qwm4-qh6w-59xr)、
[setuptools](https://github.com/advisories/GHSA-xmj3-9gf7-h52w)。

这项检查依赖 Python 包漏洞数据库，不代表对 Qt/Chromium 原生组件做了完整漏洞审计。

## 验证边界

目标配置和登录信息使用沙盒与假数据。本轮未使用真实清华账户登录，也未向真实 DSH / CC Switch
配置写入；因此不能把本地回归测试等同于真实账号、所有站点变化和所有第三方版本的兼容性保证。

模型下载的 25 秒预算限制后续请求的启动和超时分配；标准库 socket 超时并非严格的端到端墙钟截止。
Qt WebEngine 仍是发行体积的主要来源，本轮保留已选定的内置浏览器和 ZIP 主发行方式。

本轮不修改正在运行的其它便携副本与已有开机启动路径。
