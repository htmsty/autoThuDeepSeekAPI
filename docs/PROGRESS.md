## 2.0 阶段（本轮）

### 已完成

1. 全流程打通：内置浏览器取 Token、站点会话校验、DSH 凭据与 provider 写入、CC Switch
   卡片与路由写入、写入前备份、一键还原。
2. 全面排查并修掉的问题（明细见 CHANGELOG 的 2.0 一节）：
   - CC Switch：事务内 `or` 短路导致 `_update_meta()` 不执行、`apiFormat` 永远漏写、每次同步
     都误判"有变化"并重写数据库（真 bug，已加回归用例）。
   - CC Switch：加锁后重新核对卡片状态；INSERT 按实际列拼，兼容没有 `is_current` 的旧库。
   - DSH：统一模式下默认模型要指向真正被更新的 provider key（本地转发可能是 `thu-local`）。
   - DSH：`providers.madmodel` 为 null/空视为空位；写盘前回读校验 + 原子落盘。
   - 界面：等待对话框期间可能起第二轮同步（竞态）；取 Token 启动失败会卡在"忙"；
     退出时同步线程仍在跑；开机启动状态与注册表不一致、源码模式命令指错文件。
   - 基础设施：数据根目录缓存（共享目录上重复探测很慢，且两实例会互相干扰探针）；
     设置 / 状态 / 备份索引 / 配置写入改原子写；日志目录不可写不再拖垮启动。
   - 校验：站点回网页时不再白等一次 30 秒的对话请求。
3. 测试从 10 项扩到 36 项，覆盖目标写入、备份还原、模型列表解析、校验分支、设置迁移、
   界面冒烟与基础设施。

## 已知限制

- 站点前端结构与接口可能变化，模型列表与校验逻辑要跟着改。
- DSH 自己也会写 profile 文件；同步后建议重启 DSH，避免它用内存里的旧配置覆盖回去。
- CC Switch 正在运行时改它的数据库有被覆盖的风险，默认先提示关闭（可设成直接改）。
- 单文件版启动比文件夹版慢（每次要解包），日常建议用文件夹版。
