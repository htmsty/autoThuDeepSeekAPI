# 使用手册

这份手册面向**使用者**：安装、第一次登录、每个按钮和每个设置项的作用、常见问题、卸载。
开发与实现细节见 [README.md](../README.md) 与 [ARCHITECTURE.md](../ARCHITECTURE.md)。

- 程序名：Auto THU DeepSeek API
- 作者：htmsty
- 项目主页：<https://github.com/htmsty/autoThuDeepSeekAPI>

---

## 1. 它是什么

一个 Windows 便携程序：

1. 用**程序内置的浏览器窗口**打开清华大学 MadModel 平台的统一身份认证。默认你自己登录；
   也可显式保存凭据后自动登录：程序先在后台提交，成功时不显示浏览器窗口；验证码、二次验证、
   账号密码错误或页面异常时才显示窗口提醒；
2. 登录成功后程序自动捕获 Token、关掉窗口、校验 Token 是否可用；
3. 把 Token 写进你启用的目标：

   - **DeepSeek Harness（DSH）**：`.dsh\.credentials.yaml` 里的 `MADMODEL_API_KEY`，
     以及受管 profile 的 `cordis.patch.yml` 里的 `madmodel` provider；
   - **CC Switch**：供应商卡片 `DeepSeek (THU)`；当前供应商路由默认不改，需单独开启。

4. 默认每 60 分钟自动同步一次，每次在 45～75 分钟之间随机；写入前自动备份，可做字段级还原。

程序默认不模拟登录，也不把任何数据上传到别处。自动登录必须由你显式开启，密码只存
Windows Credential Manager。

## 2. 安装与启动

### 2.1 该用哪个版本

发行包里有两个形态，功能完全一样：

| 形态 | 说明 | 建议 |
| --- | --- | --- |
| 文件夹版（`autoThuDeepSeekAPI\` 目录） | 启动快、体积展开 | **日常使用推荐** |
| 单文件版（`autoThuDeepSeekAPI.exe`） | 只有一个文件，启动时要先解包（慢几秒） | 偶尔换机器时方便 |

把选好的版本放到一个固定目录（例如 `D:\Tools\autoThuDeepSeekAPI\`），双击运行即可，
不需要安装。也可以右键「发送到 → 桌面快捷方式」，或者用程序里的
「创建桌面快捷方式」按钮生成一个。

### 2.2 关于"程序放在桌面上"的提醒

如果你把程序**直接放在桌面根目录**（桌面里的子文件夹不算），第一次启动会提醒一次：
继续运行会在桌面生成 `private` 数据文件夹，里面是 Token、设置、备份和浏览器会话。

这时你可以：

| 选择 | 结果 |
| --- | --- |
| 选择 private 位置… | 把运行数据放到别处（推荐，例如 `D:\autoThuDeepSeekAPI-data`），以后不再提醒 |
| 仍然继续 | 保持现状，以后不再提醒 |
| 退出程序去换本程序位置 | 直接退出（不记"已处理"）；把程序挪到别处再运行即可 |

按 `ESC` 或点右上角 `×` 关掉这个提醒，**不算**做过选择：这一次启动会继续运行，
下次启动仍会提醒（同一次启动里不会重复弹）。

### 2.3 第一次同步

1. 打开程序，点主界面的「**立即获取并同步**」；
2. 在弹出的**内置浏览器窗口**里完成清华统一身份认证；
3. 程序检测到 Token 后会自动关闭窗口，校验并写入你启用的目标；
4. 主界面状态栏、Token 状态和系统托盘通知会显示结果；详细日志在设置里打开。

如果 DSH 与 CC Switch 都还没用过（配置目录都不存在），程序会先提醒你去装并各运行一次，
这一次同步会跳过。

## 3. 主界面

### 3.1 状态区

| 显示 | 含义 |
| --- | --- |
| DeepSeek Harness | 是否检测到 DSH 配置目录（以及有几个 profile） |
| CC Switch | 是否检测到 CC Switch 数据库 |
| Token | 当前 Token 的到期时刻（"有效至 …"）或"已过期／尚未获取" |
| 上次同步 | 最近一次同步的时间与结果摘要 |

主界面下方显示下一次自动同步的预计等待时间。底部状态栏显示运行数据目录。

### 3.2 主界面按钮

| 按钮 | 做什么 |
| --- | --- |
| 立即获取并同步 | 打开内置浏览器（已经登录过就直接静默取），拿到 Token 后校验并写入 |
| 设置… | 打开设置对话框（下面第 4 节） |
| 退出 | 真正退出程序（点窗口 `×` 默认只是最小化到托盘） |

### 3.3 托盘

- 点窗口 `×` 默认最小化到系统托盘（可在设置里改成直接退出）；
- 托盘图标**左键单击或双击**打开主界面，**右键**弹出菜单：
  打开主界面 / 立即获取并同步 / 暂停或继续自动同步 / 设置 / 退出；
- 同步成功或失败都会弹一条气泡通知。

## 4. 设置对话框

设置分为五页，底部固定为「应用 / 确定 / 取消」：应用保存但不关闭，确定保存并关闭，
取消丢弃尚未应用的修改。

### 4.1 同步

| 设置项 | 说明 |
| --- | --- |
| 自动同步 | 默认开；可由托盘菜单暂停或继续 |
| 同步间隔 | 默认 60 分钟；实际每次在 45～75 分钟之间重新随机 |
| 启动时立即同步 | 默认开 |
| 同步完成立即最小化到托盘 | 默认关 |

### 4.2 写入目标

| 设置项 | 说明 |
| --- | --- |
| 启用 DSH 写入 | DSH 总开关 |
| 更新凭据 / 更新 Provider | 两个独立开关，分别控制 `.credentials.yaml` 与 profile |
| DSH 目录 | 留空时探测环境变量、常见目录和注册表安装位置 |
| 受管 profile | 留空自动选择；也可填 `desktop`、`web` 等名字 |
| 启用 CC Switch 写入 | CC Switch 总开关 |
| 更新供应商卡片 / 激活当前路由 | 两个独立开关；后者默认关，开启后才会改 `is_current` 与路由 JSON |
| CC Switch 目录 | 留空时探测常见目录和注册表安装位置 |
| 顺带刷新同站点旧卡片 | 默认关；开启后会改其它卡片 |
| CC Switch 运行中 | 默认「先提示」；只有显式选择才直接改 |

“统一所有 profile 到 madmodel”已删除。程序只更新解析后确实是本程序 `madmodel` provider
的 profile；一份都没有时，只在一个默认 profile（优先 `desktop`）自动创建。

### 4.3 登录与安全

| 设置项 | 说明 |
| --- | --- |
| 自动登录 | 默认关闭；用户名/密码只存 Windows Credential Manager |
| 用户名 / 密码 | 修改密码后点应用；密码留空表示保留已保存密码 |
| 删除已保存凭据 | 删除 Credential Manager 中的账号密码 |
| 允许最小对话校验 | 默认关闭；开启后可能在会话接口无法判断时消耗少量额度 |

自动登录只在 `*.tsinghua.edu.cn` 页面工作。保存凭据后，手动点击同步也会先尝试后台登录，
成功时不会弹出浏览器窗口。检测到真正显示的验证码、二次验证、MFA、账号密码错误或页面结构
不明时，程序停止自动提交并打开登录窗口提醒用户接手。登录页里默认隐藏的验证码输入框不会被
误判成人工验证。

主窗口和设置窗口都会记住上次关闭时的大小。设置窗口默认 `700×540`，最小 `640×480`，内容
超出时使用滚动区；换成更小的显示器后，程序会按屏幕可用区域自动收缩。

## 5. 备份与还原

- 程序**第一次运行**时，会先把 DSH 凭据、各 profile、CC Switch 数据库与两个路由文件
  各备份一份（带 `original` 标记，永不清理）；
- 之后每次真正要写文件之前，都会再留一份普通备份（按"备份保留份数"轮换）；
- 备份文件使用 Windows DPAPI 加密，放在 `private\backups\` 下；每个快照目录里都有
  `source.txt` 记录来源文件；
- 每次成功写入还会在 `private\changes\` 记录字段级变更（同样是 DPAPI 密文）；
- 「还原到首次修改前」会从新到旧撤销本程序写过的字段；当前值已被你或别的程序改动时保留并报告冲突；
- 只有旧备份、没有字段日志时，才会在额外高风险提示后执行整文件还原；
- 清理旧备份走**回收站**，可以撤销。

## 6. 数据、隐私与安全

### 6.1 数据都在哪

默认在程序目录下的 `private\`：

```
private/
  settings.json       你的设置
  state.json          运行状态（最近 Token 为 DPAPI 密文、时间戳）
  model-cache.json    站点模型清单缓存（6 小时）
  logs/               日志（按天 + 按大小轮转）
  backups/            DPAPI 加密备份与还原索引
  changes/            DPAPI 加密字段变更日志
  browser-profile/    内置浏览器独立档案（当前用户 ACL，保存登录会话）
```

程序目录不可写时自动改用 `%LOCALAPPDATA%\autoThuDeepSeekAPI\private\`。
你把 private 位置改到别处后，位置记在 `%LOCALAPPDATA%\autoThuDeepSeekAPI\private-location.json`。
自动登录凭据单独保存在 Windows Credential Manager，不写进这些 JSON。

### 6.2 隐私

- Token、日志、备份、浏览器会话**只保存在本机**；Token/备份/变更日志用 DPAPI 加密，
  Qt WebEngine 必须直接读写的浏览器会话使用当前用户 ACL；
- 程序访问网络只有这几件事：打开清华 MadModel 站点登录页；读取站点前端包里的模型清单
  （读不到时退回站点的 `/v1/models`，再读不到就用内置名单）；向站点校验 Token 是否可用。
  日志里只记 Token 的**指纹**（16 位十六进制），不记完整 Token。最小对话校验默认关闭。

### 6.3 会不会改动我的其它配置

程序只写下面这些位置，别的文件一律不碰：

| 文件 | 只写什么 |
| --- | --- |
| `.dsh\.credentials.yaml` | `MADMODEL_API_KEY` **这一行**（保留其它 key、注释与引号风格） |
| `.dsh\profiles\<受管 profile>\cordis.patch.yml` | 键名正好为 `madmodel` 的 provider 及其被本程序管理的字段；别人的 provider、注释、缩进不动 |
| `.cc-switch\cc-switch.db` | 卡片 `(deepseek-thu, codex)`；只有开启“激活当前路由”时才调整同 app_type 的 `is_current` |
| `.cc-switch\settings.json` | 仅在开启“激活当前路由”时修改 `currentProviderCodex` |
| `.cc-switch\live-state.json` | 仅在开启“激活当前路由”时修改 `apps.codex.proxy_route` |
| `private\**` | 设置 / DPAPI 状态 / 加密备份 / 字段日志 / 浏览器会话 / 模型缓存 |

如果某个 profile 用了程序认不出来的写法（例如 provider 写成一行内联 map）而旁边又有别人的
provider，程序会**报错并跳过写入**，而不是整份重写去冒改坏别人配置的风险。

## 7. 卸载

设置 →「运行数据与维护 → 干净卸载…」，需要连续确认两次，并单独问你：

> 要不要把 DSH / CC Switch 还原到本程序第一次修改之前的备份？

- 选「是」：先还原（会覆盖这两个应用当前的配置，**有风险**，界面上有提示），再清运行数据；
- 选「否」：只清程序自己的运行数据。

新版优先按字段还原：只撤销本程序写过的字段，并跳过你后来修改过的冲突字段。只有旧备份、
没有字段日志时，才会在额外高风险确认后整文件覆盖。

然后程序会：

1. 删掉 `private` 里属于程序自己的条目（Token、设置、状态、日志、加密备份、字段日志、
   浏览器会话、模型缓存、提醒状态、单实例锁）；
2. 删掉位置指针文件；
3. **不会**删除程序自己的 exe（对话框里会告诉你具体路径，手动删即可）；
4. 你放在 private 目录里的其它文件不会被删；目录本身也保留（不整个删目录）；
5. 所有删除只走**回收站**；回收站不可用就保留原样并报告，不会永久删除；
6. 退出程序（之后不会再把设置写回磁盘）。

卸载流程只用普通文件操作，不写自删除脚本、不调用 `rd` / `del` / `reg`，不会被当成恶意行为。

## 8. 常见问题

**Q：点「立即获取并同步」后窗口一闪而过／要求登录？**

第一次运行时浏览器档案里还没有登录会话，程序会直接打开登录窗口。
完成一次登录后，会话会保存在 `private\browser-profile\`，之后就可以静默取 Token。

**Q：自动同步提示"静默取 Token 超时：多半需要重新登录"？**

说明站点会话过期了。点一次「立即获取并同步」手动登录即可；
如果你还有未过期的旧 Token，程序会沿用它继续同步。

**Q：提示"程序已经在运行"？**

同一份程序只允许开一个实例。请到系统托盘找它；如果托盘里没有，等几秒再试
（刚重启完时旧进程可能还没退干净）。如果提示是"无法在运行数据目录建立锁文件"，
按提示检查那个目录是否可写。

**Q：提示"没有检测到 DSH / CC Switch"？**

两个程序的配置目录都不存在时会出现。请先分别安装并运行一次 DSH / CC Switch，
让它们生成配置后再同步；已经装好但目录在别处时，可以在设置里手动指定目录。

**Q：提示"没有启用任何写入目标"？**

设置里 DSH 写入与 CC Switch 写入都被关掉了，至少打开一个。

**Q：提示"上一次同步还没结束"？**

点「强行终止并重试」即可：程序会在**安全的位置**停下（正在写的那一份文件先写完），
然后自动重新开始；点「取消」则什么都不做。

**Q：DSH 报 `provider "…" model "…" does not support reasoning effort "…"`？**

这是 DSH 的思考档位与模型不匹配。程序在每次同步时会把 provider 的默认思考档修正成
所有模型都支持的公共档位，并且只在"用户设的档位确实不合法"时才改，不会动你合法设置。
同步一次后重启 DSH 即可。

**Q：DSH 报"模型不存在"？**

站点的模型清单会变（改名、下架）。程序每次都从站点前端包读取当前清单并同步到 provider，
所以同步一次通常就能修好。手动往 provider 里加的模型会被站点清单覆盖，需要长期保留请提 issue。

**Q：同步日志显示"无变化"是不是没同步？**

是已经是最新状态，程序没有重复写文件（不写 = 不改动你的配置，这是有意设计）。
Token 是否有效可以看主界面 Token 状态与日志里的校验结论。

**Q：CC Switch 正在运行，会不会写坏？**

默认策略是「先提示我，由我决定」。推荐先退出 CC Switch 再继续。只有你显式改成
“直接改”时，程序才会在它运行时直接修改数据库；路由写入失败时本次卡片与路由会回滚。

**Q：自动登录失败或停在登录页？**

程序会识别隐藏验证码与真正显示的验证码，并使用清华登录页实际的 `<a>` 登录按钮提交。
验证码、二次验证、MFA、账号锁定或学校登录页改版都不会被绕过；遇到这些情况，程序会停止
自动提交并打开窗口，请手动完成验证。如果确认密码已改，请在设置里重新填写；也可以在
「登录与安全」里删除已保存凭据，恢复纯手动登录。

**Q：杀毒软件报毒？**

程序是 PyInstaller 打包的 Python 程序，部分杀软会误报。可以：
把整个程序目录加入白名单；或从源码运行（见 README）；或核对发行版的 SHA256
（`releases/<版本>/SHA256.txt`）。

**Q：想把开机启动关掉？**

设置 →「高级」里把「开机启动（最小化到托盘）」取消勾选即可（它写的是当前用户注册表启动项，
不勾就会删掉）。用第三方工具删过启动项也没关系：程序下次启动会读到"未启用"并同步界面状态。

**Q：程序在哪、配置文件在哪？**

设置 →「高级」里的「关于…」能看到版本、作者、项目主页和数据目录；
「打开数据目录」直接打开运行数据目录。

**Q：怎么反馈问题？**

在设置 →「高级 → 关于」里记下版本号；把「备份与维护 → 打开日志」里的日志文件附上，
到项目主页开 issue：<https://github.com/htmsty/autoThuDeepSeekAPI/issues>。
日志里不会出现完整 Token。

## 9. 版本与更新

- 当前版本号显示在设置 →「高级 → 关于」里；源码里对应 `constants.APP_VERSION`；
- 每个版本的改动见 [CHANGELOG.md](../CHANGELOG.md)；
- 发行版的单文件程序留档在仓库外的 `releases/<版本>/`，仓库里只记录 SHA256；
  GitHub Release 资产可以单独上传较大的 EXE，不受普通 Git 文件 100 MiB 限制。
