## 2.3 阶段（本轮）

### 已完成

1. **定位根因**：DSH 本体里 `resolveReasoningLevel(model, options.reasoningEffort ?? profile.reasoning)`
   —— 没有显式思考档时会回落到 provider 的 `reasoning`，而 `DeepSeek-V4.1-Flash` 只支持
   `low/high/max`，所以固定写 `medium` 必然报 `UNSUPPORTED_REASONING_EFFORT`；第一次运行
   还没写 `agent-default-model.reasoningEffort`，一定走回落，所以"第一次运行"最容易中招。
2. **三条修法**：provider 级 `reasoning` 取所有模型支持档位的交集（没有就不写）；
   默认模型总是写显式且合法的 `reasoningEffort`；预检把这两条作为硬性检查。
3. **日志口径**：把"无需改写"那句明确成文件比对（带 Token 指纹、注明不做网络校验），
   并把真正的站点校验那条日志标成"向站点发起会话校验请求"。
4. **真实配置已修**：desktop/web 的 `provider.reasoning` 由 `medium` 改为 `low`，
   web 的默认模型补上 `high`；改动前留底。
5. 测试 52 → 56 项；打包并留档 `releases/2.3/`，提交并打 tag `v2.3`。

## 2.5.1 阶段（本轮）

真机试 2.5 报回来的四个问题，逐条修完：

1. **旧 private 删不干净**：搬家/卸载前先放开占用（取消取 Token、`deleteLater()` +
   显式 `DeferredDelete` 释放 WebEngine 档案、关闭文件日志句柄、让出单实例锁）；
   清空到只剩程序自己的东西时连目录一起删；万一还被占着就在指针里留重试标记，下次启动继续清。
2. **删除改走回收站**：`paths.recycle_path()`（Shell `SHFileOperation` + `FOF_ALLOWUNDO`），
   回收站不可用才永久删除并说明。
3. **重启被判"程序已经在运行"**：抽 `instance.py` 管锁，重启/卸载前主动让出，
   新进程启动时重试拿锁（最多 6 秒）。
4. **提醒前就建了 private**：`paths.defer_creation()` 让启动早期只判断不落盘，
   桌面提醒改到 `app.py` 最前面（建日志、建锁之前）；按钮文案改成「退出程序去换本程序位置」。

验证：测试 88 → 96 项全绿；两个真机场景脚本（浏览器开着换位置、浏览器+日志+锁全开着卸载）
都跑通；设置对话框截图复检；版本 2.5.1 打包留档。

## 2.5.2 阶段（本轮）

按要求做了一次全面检修，专门找"新功能 vs 旧逻辑"的冲突，修掉 7 处（明细见 CHANGELOG 2.5.2）：

1. **严重**：同标签连续备份全挤进一个快照目录 → 旧备份永远清不掉、磁盘越占越多。
   修法：只有显式 `begin_snapshot()` 的批次才复用目录，普通备份各占一个。
2. 自动同步会弹「强行终止并重试」→ 只有手动点同步才问，自动同步安静跳过。
3. 搬位置/卸载期间可能被自动同步插入 → 新增 `_maintenance` + 期间停计时器。
4. 「恢复默认设置」还原 private 位置时绕过安全流程（会重现删不掉）→ 改走同一条流程。
5. 备份轮换没走回收站 → 统一走 `paths.delete_path()`。
6. 提醒文案里取 `data_root()` 仍会先建目录 → 提醒全程"延迟创建"。
7. 重复启动干等 6 秒 → 只有 `--restarted` 才等 6 秒，正常启动 0.6 秒。

验证：测试 96 → 105 项全绿；真实启动流程冒烟通过；版本 2.5.2 打包留档。

## 怎么回退

每个大版本都打了 tag，出问题可以按下面三种粒度回退（都不会动 `private/` 里的运行数据）：

```powershell
git log --oneline --decorate          # 看清哪个 commit 对应哪个版本
git revert <2.1 的提交>               # 只回退 2.1 的改动，保留历史（推荐）
git checkout v2.0                     # 直接回到 2.0 的代码
git checkout v2.1                     # 再回到 2.1
```

程序本身也有两层"回退"：

- **一键还原**（主界面按钮）：把 DSH / CC Switch 的配置文件恢复成最早的备份（第一次修改前），
  还原前会先备份当前状态，所以还原本身也能再退回来。
- **手动备份**：随时留一份现状；备份都在 `private/backups/`，`index.json` 里记着每份的来源与校验和。
