## 2.7.1 阶段

1. **自动登录根因**：清华统一身份认证页在 DOM 中始终保留一个隐藏的验证码输入框，
   旧脚本把它误判成人工验证；页面「登录」实际是 `<a onclick="doLogin()">`，旧脚本只找
   button，所以即使填了密码也不会提交。现在只认真实可见的验证码，并覆盖可见的
   button/input/a/role=button 登录控件。
2. **浏览器弹出行为**：保存自动登录凭据后，手动同步也先使用隐藏的后台窗口尝试登录；
   只有验证码、二次验证、账号密码错误或页面异常时才显示窗口。
3. **窗口尺寸**：设置窗口默认 `700×540`、最小 `640×480`；主窗口和设置窗口尺寸存进
   `private/state.json`，重启后恢复，并按屏幕可用区域限制。
4. 验证：相关 42 项测试首轮全绿，随后跑全量测试、两版打包与自检。

## 2.7.3 阶段

1. **根因**：构建运行时定制的 `ssl.py` 创建 `SSLContext` 时固定读取
   `codex-rejected-cas.pem`；PyInstaller 未自动包含该数据文件，于是模型列表请求在 TLS
   初始化阶段抛出 `FileNotFoundError`。
2. **打包修复**：把证书文件放到 `_MEIPASS` 根目录，同时保留在 `assets/`。
3. **运行时兜底**：新增 `http_tls.py`，默认 CA 初始化失败时从 Windows `CA` / `ROOT`
   证书库加载根证书，仍保持证书链与主机名校验。模型下载、Token 校验、站点探测全部使用该入口。
4. **防崩**：TLS 初始化异常会被转换为“本次模型读取失败 / Token 暂无法校验”，
   同步会回退内置模型继续，不再整次失败。
5. 验证：全量 187 项测试全绿；强制模拟缺 CA 后实际连接 MadModel 返回 HTTP 200；
   两版打包、包内证书文件、`--selftest` 与文件版本核对通过。

## 2.3 阶段（本轮）

### 已完成

1. **定位根因**：DSH 本体里 `resolveReasoningLevel(model, options.reasoningEffort ?? profile.reasoning)`
   —— 没有显式思考档时会回落到 provider 的 `reasoning`，而 `DeepSeek-V4.1-Flash` 只支持
   `low/high/max`，所以固定写 `medium` 必然报 `UNSUPPORTED_REASONING_EFFORT`；第一次运行
   还没写 `agent-default-model.reasoningEffort`，一定走回落，所以"第一次运行"最容易中招。
2. **三条修法**：provider 级 `reasoning` 取所有模型支持档位的交集（没有就不写）；
   默认模型总是写显式且合法的 `reasoningEffort`；预检把这两条作为硬性检查。
3. **日志口径**：把"无需改写"那句明确成文件比对（带 Token 指纹、注明不做网络校验），
   并把真正的站点校验那条日志标成"向站点发起会话校验请求"。
4. **真实配置已修**：desktop/web 的 `provider.reasoning` 由 `medium` 改为 `low`，
   web 的默认模型补上 `high`；改动前留底。
5. 测试 52 → 56 项；打包并留档 `releases/2.3/`，提交并打 tag `v2.3`。

## 已知限制

- 站点前端结构与接口可能变化，模型列表与校验逻辑要跟着改。
- DSH 自己也会写 profile 文件；同步后建议重启 DSH，避免它用内存里的旧配置覆盖回去。
- CC Switch 正在运行时改数据库有被覆盖的风险。2.7 起默认**先提示**，且路由激活默认关闭。
- DPAPI 密文只能由同一 Windows 账户解密；浏览器档案受当前用户 ACL 保护，不额外加密。
- 单文件版启动比文件夹版慢（每次都要解包到临时目录），日常建议用文件夹版。

## 怎么回退

每个大版本都打了 tag，出问题可以按下面三种粒度回退（都不会动 `private/` 里的运行数据）：

```powershell
git log --oneline --decorate          # 看清哪个 commit 对应哪个版本
git revert <2.1 的提交>               # 只回退 2.1 的改动，保留历史（推荐）
git checkout v2.0                     # 直接回到 2.0 的代码
git checkout v2.1                     # 再回到 2.1
```

程序本身也有两层"回退"：

- **一键还原**（主界面按钮）：把 DSH / CC Switch 的配置文件恢复成最早的备份（第一次修改前），
  还原前会先备份当前状态，所以还原本身也能再退回来。
- **手动备份**：随时留一份现状；备份都在 `private/backups/`，`index.json` 里记着每份的来源与校验和。
